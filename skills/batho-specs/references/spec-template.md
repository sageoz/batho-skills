# Spec Template — the grounded truth (canonical, shared by batho-specs / execute / review)

Copy this skeleton into `batho-specs/NN-<name>/specs_<name>.md`. Section-by-section
guidance says which Batho tool fills it. Rules that make the spec "grounded":

- Every row in §2 cites `entity_id` + `file:line`. Zero-citation rows are invalid.
- §3 is the agent's anchor set: batho-execute re-resolves these IDs before editing.
- §5 (blast radius) and §6 (coverage) are recomputed and diffed at review time.

## Section-by-section filling guide

| Section | Batho tool(s) | Notes |
|---------|---------------|-------|
| §2 Current Behavior | `get_entity`, `get_file_graph` | one row per observable behavior; cite the entity that implements it |
| §3 Entity References | `search_entities` → `get_entity` | include relationship counts from `get_entity` output |
| §4 Proposed Changes | — (author's plan) | each row must map to ≥1 §3 entity or declare "new entity" |
| §5 Blast Radius | `graph_query(incoming)`, `trace_path`, `file_connectivity` | risk tiers in batho-execute `references/risk-tiers.md` |
| §6 Coverage | `file_connectivity` (test surface) | criteria here are what batho-review verifies |
| §10 Provenance | `batho_status` | record `artifact_generation` at write time |
